## Розподіл часу

| Тема | Частка |
| --- | ---: |
| JavaScript та асинхронність | 20% |
| React | 20% |
| Практичні завдання | 15% |
| TypeScript | 12% |
| Англійська та професійний досвід | 10% |
| Redux Toolkit та RTK Query | 8% |
| Браузер, мережа, HTML і CSS | 8% |
| Тестування та архітектура | 7% |

Це орієнтир, а не правило. Більше часу віддавай темам, які прямо згадані у вакансії, і тим, де картки найчастіше отримують статус «Повторити».

## Як тренуватися з карткою

1. Увімкни режим «Співбесіда» — відповідь буде прихована.
2. Прочитай питання й відповідай уголос англійською 60–90 секунд: суть, як це працює, практичний наслідок.
3. Відкрий відповідь. Порівняй з англомовним блоком, послухай його кнопкою «Озвучити», переглянь українське пояснення.
4. Оціни себе: «Знаю, далі» або «Ще повторю». Картки «Повторити» й закладки збираються в режимі «Повторення».
5. Якщо є блок «Можливі уточнення», відповідай і на них — саме там інтерв’юер перевіряє глибину.

## Як має відрізнятися відповідь Junior від Middle?

Наприклад, питання: **«Що таке useCallback?»**

**Junior:**

useCallback — це hook, який мемоізує функцію.

**Middle:**

useCallback дозволяє зберігати стабільне посилання на функцію між рендерами, поки не змінюються її залежності. Це корисно, коли функція передається мемоізованому дочірньому компоненту або використовується як залежність іншого hook. Сам по собі useCallback не запобігає ререндеру компонента, а його надмірне використання може бути зайвим.

**Senior:**

Спочатку я б визначив, чи стабільність посилання взагалі має значення в цьому сценарії. Якщо є проблема з продуктивністю, перевірив би її через Profiler. Також розглянув би зміну структури компонентів або усунення зайвої залежності замість додавання мемоізації. Якщо в проєкті ввімкнено React Compiler, більшість ручної мемоізації можна прибрати.

Це умовні приклади, а не універсальні критерії рівня розробника.
