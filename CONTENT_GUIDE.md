# Як писати й редагувати картки

Цей файл описує формат Markdown у `content/`. Збірка (`npm run build`) перетворює його на `index.html`, а тести (`npm test`) перевіряють, що формат дотримано.

## Структура розділу

Кожен розділ — це файл `content/NN-slug/README.md`. Перший рядок — заголовок розділу `# Назва`. Після нього може йти короткий вступ. Далі — картки.

## Структура картки

````markdown
## 3.12. Що таке stale closure?

<a id="q-3-12"></a>

Необов’язкова умова. Для практичних завдань тут текст задачі та вихідний код.

### Пояснення

#### Interview answer (EN)

Two to four natural sentences that you could say out loud in an interview.

Українське пояснення: абзаци, таблиці, приклади коду, схеми.

#### Можливі уточнення

- **Як виправити stale closure в інтервалі?** — functional update або ref.

#### Пов’язані питання

- [Як працює `useEffect`?](#q-3-7)
- [Closure](../09-live-coding/README.md#q-9-2)

#### Документація

- [React — Removing Effect Dependencies](https://react.dev/learn/removing-effect-dependencies)
````

Правила:

- Номер у заголовку й ідентифікатор `q-N-M` збігаються. Нумерація всередині розділу йде без пропусків. Наявні номери не змінюються, бо на них спираються прямі посилання та збережений прогрес. Нові картки додаються в кінець розділу.
- `### Пояснення` — для звичайних питань, `### Розв’язок` — для задач. Розв’язок у режимі навчання закритий, доки користувач не спробує сам.
- `#### Interview answer (EN)` обов’язковий і стоїть першим після `### Пояснення`/`### Розв’язок`. Це 2–4 речення (приблизно 35–90 слів) природної усної англійської: головна думка, механізм або причина, практичний наслідок чи компроміс. Без маркованих списків, без коду.
- Решта підрозділів (`Можливі уточнення`, `Пов’язані питання`, `Документація`) необов’язкові й ідуть саме в такому порядку в кінці картки.
- `Можливі уточнення` — 2–4 запитання, які інтерв’юер може поставити далі, з короткою підказкою.
- `Документація` — 1–3 посилання тільки на офіційні або першоджерела (MDN, react.dev, typescriptlang.org, redux-toolkit.js.org, web.dev, специфікації W3C/WHATWG/IETF, документація інструментів). Лише `https://`. Перелік дозволених доменів — у `tests/handbook.test.mjs`.
- Внутрішні посилання: `#q-N-M` у межах розділу або `../NN-slug/README.md#q-N-M` між розділами.

## Спеціальні блоки коду

| Мітка | Що відбувається |
| --- | --- |
| ` ```javascript ` / `typescript` / `tsx` / `css` / `html` / `bash` / `json` / `sql` | Звичайний приклад з підсвічуванням і кнопкою копіювання |
| ` ```javascript run ` | Приклад можна запустити й відредагувати в браузері. Лише чистий JS: `console.*`, таймери, Promise, `queueMicrotask`, async/await. Без DOM, мережі та імпортів. Має завершуватися за секунду |
| ` ```flow ` | Покрокова схема: кожен рядок `Назва кроку \| пояснення` |
| ` ```demo ` | Вбудовує інтерактивну демонстрацію з `scripts/demos/`. У блоці — лише назва демо |

Діаграми SVG лежать у `content/diagrams/` і підключаються як `![Підпис](../diagrams/назва.svg)` окремим абзацом. SVG мають бути без скриптів і зовнішніх посилань; у них потрібен `viewBox`.

## Інтерактивні демо

Демо лежать у `scripts/demos/`: `<назва>.html` — розмітка, `<назва>.js` — функція `(root) => { … }`, яка отримує контейнер демо. У збірку потрапляють лише ті демо, які використано в картках. Усередині демо не використовуй `id` — одне демо може трапитися на сторінці кілька разів.

| Демо | Що показує |
| --- | --- |
| `event-loop` | Call stack, microtasks і tasks крок за кроком на трьох прикладах |
| `debounce-throttle` | Виклики debounce і throttle на шкалі часу для реальних подій |
| `specificity` | Калькулятор specificity двох селекторів |
| `box-model` | `content-box` проти `border-box` із повзунками |
| `batching` | Три виклики `setCount` зі значенням і з функцією |
| `bva` | Класи еквівалентності та граничні значення для числового діапазону |
| `pairwise` | Генератор all-pairs набору тестів |
| `flaky` | Імовірність зеленого прогону з флакі-тестами й ретраями |
| `sql-joins` | INNER, LEFT, RIGHT, FULL і anti-join на двох таблицях |

## Налаштування посібника

`handbook.config.json` задає назву, роль, опис, ключ `localStorage`, кольорову палітру (`indigo` або `teal`) і посилання на репозиторій. `stableCounts` — кількість карток у розділах попереднього видання: тест перевіряє, що ці ідентифікатори не зникли.

## Стиль

- Пояснення українською, технічні терміни — як прийнято в індустрії (`closure`, `re-render`, `cache key`).
- Спершу суть, потім деталі та нюанси. Неточні спрощення позначай словами «спрощено», «зазвичай».
- Код має бути коректним і мінімальним. Якщо приклад навмисно хибний, познач це в тексті («Неправильно:»).
- Не вигадуй цифри, версії та API. Якщо щось залежить від версії бібліотеки, назви версію.
